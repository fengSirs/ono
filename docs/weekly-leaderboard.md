# 每周首次达成榜

## 规则与接口

巴西利亚自然周从周一 00:00 至下周一 00:00（结束时刻不包含）。沿用活动 UTC-03:00 日历。前 100 位首次完成养成的用户即时取得申领资格；以后完成者仍保留养成记录，不能改在后续周再次参赛。每个正式活动身份只可申领一次，现有申领的联系方式去重仍有效。

跨周无需清空钱包、宠物或依赖定时清库任务。按服务端时间将新完成记录放入新周，历史榜单与既有资格保留。保持原活动养成与申领截止时间、库存和人工审核流程；周榜不会延长活动期限。

鉴权接口为 `POST /v1/game`，请求 `{"op":"christmasLeaderboard"}`，可添加 `"week":"2026-11-23"` 指定周一日期。榜单与规则对未登录访客开放：不带 `Authorization` 也可读取公开榜，此时 `own` 为 `null`、`entries[].isMe` 均为 false；其余活动操作仍需登录。响应包装为 `{ "leaderboard": { ... } }`，包括 `week/currentWeek/startsAt/endsAt/timezone/limit/completed/remaining/eligible/hasClaim/own/entries/previousWeek/nextWeek/closed/now`。结束毫秒值为下周一零点的排他边界。`own` 始终表示本人首次完成记录，即使正在看其他周；`entries` 只返回选中周前 100 名的昵称、名次、达成时间和是否本人，不泄露联系方式、登录令牌或内部玩家 ID。

普通养成快照新增轻量 `weekly` 汇总。申领接口在服务器校验完成记录，未养满返回 `turkeyNotGrown`，榜外返回 `weeklyNotQualified`，历史时间无法核实返回 `rankingReview`。资格保留不等于申领窗口永久开放，原有活动开关和申领截止仍生效。

## 迁移与一致性

迁移新增 `christmas_completions`，并向 `christmas_claims` 增加 `completion_id`。完成记录与喂养账本、钱包在同一事务写入。事务串行化和唯一索引保证同周同名次唯一、同活动同身份仅一次完成记录，不接受客户端传入的排名或达成时间。

可恢复的历史数据按喂养流水首次达到当前养成目标的时间回填，并以流水 ID 稳定打破同毫秒并列。缺少可信达成时间的旧记录标为 `legacy_unknown`，不制造新时间占本周名额。已有申领保留原审核状态。部署前需备份生产库，并在副本上核对历史目标配置、恢复排名及未知记录；本轮仅迁移独立的本机临时测试库，没有访问生产数据。

```sql
SELECT campaign, player, wallet FROM christmas_completions WHERE source='legacy_unknown';
```

## 验证

65 项自动测试通过，原生页面结构和三语引用检查通过。包括第 100/101 名资格、101 人并发、周日最后一毫秒、跨年和跨周、重复请求、事务回滚、历史记录隔离、预览/正式隔离、接口鉴权、历史周参数校验，以及页面请求乱序与后台定时器清理。本轮没有操作预览或完成新增页面的真机验收。
